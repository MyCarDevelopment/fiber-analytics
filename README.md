## Общие фрахты и расчёт доставки по складам (V2)

Действующую базу обновить одним файлом: `supabase/migrations/002-shared-freight.sql`. Выполнить в Supabase SQL Editor и обновить кабинет. Миграция сохраняет историю и применима повторно. Сайт определяет версию базы по `fa_settings.workflow_version` и показывает уведомление, пока обновление не установлено; новые формы записи требуют V2.

Любой активный сотрудник (включая продажи) может создавать и обновлять общие маршруты и ставки. Автор фиксируется сервером, прошлые ставки неизменяемы. Продажи не получают права изменять цены поставщиков. Старые маршруты сохраняются без автоматического определения типа: один раз вручную указать `kind` (sea/FCA) и `loading_point` в «Условиях».

Поставщик и цена не привязаны к складу в новых карточках. В сводке по умолчанию показана база в рублях без добавления доставки, для CPT — цена с уже включённой доставкой. «Доставка» раскрывает ставки и себестоимость по складам. Тип и нормализованный пункт отгрузки должны совпадать точно; по свободному тексту маршрут не угадывается. При нескольких ставках показаны варианты и диапазон, без скрытого выбора самого дешёвого фрахта. Расчёт включает товар, указанную логистику и расчётный НДС, но не отдельные таможенные платежи и прочие расходы.

Китай — FOB с морскими маршрутами, Узбекистан — FCA с доставкой по регионам, Иран — CPT без повторного фрахта. В USD-котировках поле курса CNY отсутствует; V2 сохраняет NULL вместо фиктивного курса. Для CNY цена пересчитывается по CNY/RUB, а USD/RUB нужен для долларовых ставок доставки. Это же поведение добавлено в личный калькулятор. Исторические записи сохраняют прежние значения.

Проверки: `node tests/freight-v2-db.test.mjs`, `node tests/currency-fields.test.mjs`, остальные тесты команды. Новый `supabase/install-with-logins.sql` включает V2 для чистой установки; повторно запускать его на действующем проекте не нужно.

# @fiberanalytics_bot — Cloudflare Workers

Telegram-бот для расчёта закупки волокна до пяти складов. Основной вариант запуска — Cloudflare Workers Free с SQLite Durable Objects, без постоянно работающего Python-сервера. В рамках бесплатных лимитов плата не требуется; при исчерпании лимитов сервис может перестать обрабатывать запросы. Актуальные лимиты и доступность Free проверяйте в Cloudflare. Не включайте платный Workers Paid для этого проекта.

## Возможности и ограничения

Пошаговый ввод: материал, склад, базис, пункт и дата котировки, цена, загрузка, курсы, доставка USD/RUB. Иран CPT уже включает доставку до согласованного пункта; бот не добавляет её повторно. Узбекистан FCA и Китай FOB: введённая доставка делится на фактическую загрузку. Склады: Екатеринбург, Новосибирск, Ратмирово, Краснодар, Иваново. Сценарии роста доставки на 10/20% для FCA/FOB. Доступ по Telegram ID, только личные чаты.

Это калькулятор товара и указанной доставки. Пошлины, НДС, сборы, страхование, финансирование отдельно не рассчитаны. Импорт фотографий, база предложений, рыночные данные и автоматические прогнозы пока отсутствуют. CPT требует совпадения согласованного пункта с выбранным складом. Ставки и курсы вводятся пользователем.

## Настройка с телефона — один раз

1. Создайте аккаунт на https://dash.cloudflare.com/ и откройте Workers & Pages. Включите бесплатный Workers Free и выберите поддомен workers.dev, если предложено. Платный Render для этого варианта не нужен. Если раньше создали Render worker, остановите его, чтобы не работал второй экземпляр.
2. Скопируйте Account ID из панели Cloudflare. В **My Profile → API Tokens → Create Token** выберите шаблон **Edit Cloudflare Workers**, ограничьте своим аккаунтом. Токен должен разрешать развёртывание Workers, управление Durable Objects и чтение поддомена Workers. Домены/зоны для workers.dev не требуются. Используйте API token, а не Global API Key.
3. В GitHub откройте репозиторий → **Settings → Secrets and variables → Actions → Secrets → New repository secret**. Account ID уже указан в workflow. Добавьте три секрета:
   - `CLOUDFLARE_API_TOKEN` — созданный Cloudflare API token;
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `WEBHOOK_SECRET` — новая случайная строка из менеджера паролей: 32 или более латинских букв и цифр (разрешены также `_` и `-`, максимум 256 символов). Не используйте токен бота как этот секрет.
4. Откройте **Actions → Deploy Telegram bot to Cloudflare → Run workflow → Run workflow**. Запуск только ручной: загрузка кода не развёртывает его автоматически. Workflow проверяет код, размещает Worker, записывает зашифрованные секреты и подключает webhook. При первом запросе действия GitHub может попросить включить Actions.
5. После зелёного результата отправьте https://t.me/fiberanalytics_bot команду `/id`. До настройки списка доступа расчёты закрыты.
6. В GitHub **Settings → Secrets and variables → Actions → Variables** добавьте переменную `ALLOWED_USER_IDS` со своим числовым ID. Для коллег — ID через запятую без пробелов. Снова запустите workflow. Теперь `/start` и `/calculate` доступны указанным пользователям.

Секреты не отправляйте в чат, не кладите в файлы репозитория и не вставляйте в адресную строку. Account ID и Telegram user ID не являются паролями. Если workflow сообщает, что установлен другой webhook, сначала выясните, какое приложение использует бота: сценарий не заменяет чужой webhook автоматически.

## Данные и работа

SQLite Durable Object хранит последнюю обработанную update_id и незавершённый расчёт каждого пользователя, без отдельного создания базы. Завершённый расчёт не хранится в приложении, но остаётся в Telegram. `/cancel` очищает незавершённый ввод. Защищённый endpoint `/telegram` проверяет секретный заголовок Telegram. Обработка повторов не продвигает диалог дважды; при сетевом сбое после отправки ответа Telegram возможно повторное сообщение.

GitHub-репозиторий содержит только код, а не коммерческие цены. Логи HTTP-запросов отключены в конфигурации Worker. Не запускайте Python polling одновременно с webhook.

## Проверки и структура

`node --test worker/*.test.mjs` — расчёты, защита webhook, пошаговый CPT, доступ и повторы Telegram. Рабочая версия: `worker/index.mjs`, `wrangler.jsonc`, `.github/workflows/cloudflare.yml`, `scripts/webhook.mjs`.

Старые `bot.py`, `calculator.py`, `test_calculator.py`, `render.yaml` относятся к альтернативной Python-версии и не используются Cloudflare. Настройка GitHub Actions не проверена на реальном аккаунте Cloudflare до добавления секретов. Факт загрузки кода не означает, что бот уже запущен.
