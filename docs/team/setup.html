Подключить общую базу

Интерфейс подготовлен. Для реального входа и синхронизации нужно один раз создать проект Supabase и подключить почту. Личный калькулятор продолжает работать отдельно. Никакие локальные таблицы не отправляются в базу автоматически.

1. Создайте проект

Зарегистрируйтесь на Supabase, создайте организацию и проект на Free. Пароль базы сохраните в менеджере паролей. Не отправляйте его в чат или GitHub. Бесплатный тариф имеет лимиты и условия приостановки неактивных проектов; проверьте текущие условия в панели.

2. Создайте таблицы и права

Откройте файл team.sql → Raw → скопируйте весь текст. В Supabase откройте SQL Editor → New query, вставьте и нажмите Run. Скрипт рассчитан на одно применение к новому проекту; при повторном запуске не удаляйте существующие таблицы.

3. Добавьте первого руководителя

В SQL Editor выполните следующий запрос, заменив имя и адрес на реальные. Этот запрос с личной почтой оставьте только в Supabase, не сохраняйте в публичном репозитории.

insert into public.fa_members(email, name, role)
values (lower('YOUR-EMAIL@example.com'), 'Имя руководителя', 'lead');

После входа руководитель добавит трёх менеджеров и двух сотрудников продаж через раздел «Управление». Каждый адрес получает свою роль; закрытая база проверяет права при каждом запросе.

4. Настройте доставку кодов

В Authentication → Providers / Sign In включите Email и оставьте подтверждение почты включённым. База также проверяет, что адрес действительно подтверждён. В Email Templates для Magic Link и Confirm signup добавьте в письмо код {{ .Token }}. Именно код вводится на сайте; ссылка для входа не используется.

Для личных адресов шести сотрудников обычно требуется Custom SMTP. Стандартный SMTP Supabase ограничен авторизованными адресами команды проекта и не предназначен для обычной рассылки пользователям. Подключите почтового провайдера по его инструкции, задайте адрес отправителя и при необходимости подтвердите домен. Некоторые провайдеры имеют бесплатную квоту; доступность и стоимость проверяются у провайдера. Эти SMTP-пароли вводятся только в Supabase.

В Authentication → URL Configuration задайте Site URL: https://mycardevelopment.github.io/fiberanalytics-bot/team/. Не отключайте лимиты запросов кодов. Создание учётной записи через OTP может быть доступно постороннему адресу, но таблицы и данные доступны только активным адресам из fa_members.

5. Подключите сайт

В Project Settings → Data API / API Keys скопируйте Project URL и publishable key или старый ключ anon. Это публичные параметры подключения. Secret key, service_role и пароль базы использовать нельзя.

На странице команды раскройте «Подключение базы» и сохраните URL и публичный ключ. Эта настройка действует в данном браузере. Чтобы все сотрудники пользовались подключением без настройки, эти два публичных значения можно указать в config.mjs и дождаться публикации GitHub Pages. Секретные ключи туда не добавляются.

6. Проверьте доступ

  1. Руководитель запрашивает код на свою почту и входит.
  2. В «Управлении» добавляет сотрудников: manager — 3 человека, sales — 2 человека.
  3. Менеджер входит и создаёт маршрут, добавляет ставку, затем карточку поставщика/материала и цену.
  4. Отдел продаж входит со своей почтой и видит сводку и историю, без кнопок редактирования.
  5. Проверьте, что сотрудник без доступа не видит данные, а менеджер не меняет чужую карточку.

Как пользоваться ежедневно

«Обновить цену» подставляет предыдущую цену и курсы — достаточно изменить нужное и дату. «Без изменений» подтверждает прежнюю цену и курсы на сегодня. Фрахты обновляются отдельно. Сводка использует последнюю цену, последние ставки и курсы котировки. Старая котировка в истории хранит свои условия и ссылку на ставку, известную при внесении.

График показывает цену поставщика в его валюте только для сопоставимых условий. НДС — расчётная надбавка к товару и доставке; таможенная база и пошлины отдельно не рассчитываются. Одна карточка — одна марка, условия и склад. Для разных складов создавайте отдельные карточки.

Что хранится

Котировки, фрахты и история — в Supabase. В браузере на время вкладки хранится сессия входа; выйдите из аккаунта на общем компьютере. Кнопка выхода очищает данные общего раздела из интерфейса. Сравнения личного калькулятора остаются локальными. Рекомендуется регулярно экспортировать рабочие данные и настроить резервное копирование с учётом возможностей тарифа.
