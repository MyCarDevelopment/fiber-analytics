Обновление действующего сайта

Если вход уже работает, выполните только 002-shared-freight.sql в SQL Editor, затем нажмите «Обновить» в кабинете. Данные и история сохраняются. Для старых маршрутов один раз укажите тип фрахта и точный пункт отгрузки в «Условиях». Тип и пункт автоматически не угадываются.

После обновления фрахты могут добавлять и обновлять все активные сотрудники, в том числе продажи. Права на цены поставщиков не меняются: менеджеры ведут свои карточки, продажи их только читают.

Сайт уже настроен на ваш проект Supabase. Для запуска нужно установить таблицы и создать учётные записи с паролями. Почтовые ящики, SMTP и письма для входа не нужны.

1. Установите базу

Если таблиц fa_* ещё нет, откройте готовый SQL-файл → Raw → скопируйте весь текст. В SQL Editor проекта вставьте его и нажмите Run. Он создаст защищённые таблицы и шесть профилей с ролями. Он не создаёт пароли.

Если вы уже выполняли team.sql, не запускайте установку повторно. Выполните только logins.sql. Существующие данные и назначения этот файл не перезаписывает.

2. Создайте шесть учётных записей

Откройте Authentication → Users. Для каждой строки ниже выберите Add user → Create new user, введите служебный идентификатор в поле Email и задайте отдельный надёжный пароль — рекомендуем не короче 12 символов. Включите Auto Confirm User / автоподтверждение. Используйте именно создание пользователя, а не отправку приглашения.

Эти адреса — технические идентификаторы, а не реальные почтовые ящики. На сайте сотрудники вводят только короткий логин и пароль. Пароли не добавляются в SQL, код GitHub или переписку. Передайте каждому его начальный пароль лично через защищённый канал.

3. Закройте самостоятельную регистрацию

В Authentication → Sign In / Providers оставьте Email/password как механизм Supabase Auth, но отключите Allow new users to sign up. Пользователей создаёт администратор через панель. Регистрации на сайте нет. Не отправляйте письма подтверждения: созданные пользователи должны быть автоподтверждены.

4. Проверьте работу

  1. На странице команды войдите как head с заданным паролем.
  2. В «Управлении» замените названия «Менеджер 1» и т. п. на реальные имена. Профили и роли уже подготовлены.
  3. Менеджер создаёт маршрут и ставку, затем карточку поставщика/материала и котировку. Для CPT отдельный маршрут не нужен: доставка включена в цену до указанного склада.
  4. Продажи входят как sales1 или sales2 и видят сводку и историю. Цены поставщиков доступны только для чтения; общие фрахты могут обновлять все.
  5. Каждый сотрудник может сменить свой пароль кнопкой «Сменить пароль», введя текущий и новый пароль.

Новые сотрудники и восстановление

Для нового сотрудника администратор сначала создаёт Auth-пользователя по правилу логин@fiberanalytics.invalid, затем руководитель добавляет логин и роль в «Управлении». Этот раздел управляет доступом к данным, но не создаёт учётную запись Supabase Auth.

При утере пароля обратитесь к администратору Supabase: он может установить новый через официальный Auth Admin API. Кнопка отправки письма восстановления для служебных идентификаторов не используется. Административный service_role / secret key нельзя вводить на сайт или присылать в чат.

Как считается сводка

«Без изменений» подтверждает цену и курсы на сегодня. Фрахты обновляются отдельно. Без выбора склада сводка показывает цену поставщика в рублях без дополнительной доставки. В «Доставке» выбираются ставки по складам с тем же пунктом отгрузки и типом. Морские — Китай/FOB, FCA — Узбекистан/регионы, CPT — Иран с доставкой внутри цены. Для долларовой цены курс юаня не требуется. В истории остаются прежние условия. График показывает динамику цены в исходной валюте при сопоставимых условиях. НДС — расчётная надбавка к товару и доставке, без отдельной таможенной базы.

Одна карточка — поставщик, материал и пункт отгрузки. Для FCA/FOB склад выбирается в расчёте доставки. Менеджер видит свои карточки, руководитель и продажи — общую сводку. При отключении профиля доступ блокируется на уровне базы, даже если старая сессия ещё не истекла. Локальные таблицы личного калькулятора остаются отдельно и не переносятся автоматически.

Параметры подключения

Project URL и публичный publishable key уже записаны в конфигурации сайта. Этот ключ не даёт административного доступа: с ним нельзя создать таблицы или учётные записи. Реальные коммерческие данные доступны только после входа и проверки роли базой.
